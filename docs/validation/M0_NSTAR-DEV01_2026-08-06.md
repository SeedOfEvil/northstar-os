# M0 validation: NSTAR-DEV01

Date: 2026-08-06
Host: FreeBSD 15.1-RELEASE-p2, amd64, UEFI, root-on-ZFS

## Passed evidence

- `make check-host` passed the exact userland/kernel release, amd64
  architecture, UEFI boot method, ZFS root, and boot-environment checks.
- The bootstrap ran successfully twice. The second run returned zero and
  reported all manifest packages already installed, `dbus_enable=YES`,
  `seatd_enable=YES`, the `video` group membership already present, and both
  services already running.
- The bootstrap captures were written under `/tmp/northstar-m0-bootstrap-*`;
  the latest capture recorded FreeBSD 15.1-RELEASE-p2, amd64, UEFI,
  `zroot/ROOT/default`, and the resolved package set.
- The user-local nested Wayfire v0.10.1 build passed. The visible noVNC
  `startx` session launched Xorg/scfb, nested Wayfire, QTerminal, and
  Xwayland as the unprivileged `northstar` user.
- `make vm-smoke NORTHSTAR_WAYFIRE_BIN="$HOME/.local/wayfire-nested/bin/wayfire"`
  and `sh tests/vm/m0-smoke.sh --launch` passed. QTerminal, Firefox, and
  `xterm` through Xwayland all launched in the nested session.
- The live session used `XDG_RUNTIME_DIR=/var/run/xdg/northstar`,
  `WAYLAND_DISPLAY=wayland-1`, `DISPLAY=:3`, and the expected user Xauthority
  file. Diagnostics were collected separately; an SSH-launched diagnostics
  process does not inherit the visible session environment, so the live
  `procstat` evidence is the authoritative session check.
- After installing `xf86-input-libinput-1.5.0` and restarting Xorg, the
  QEMU USB Tablet was loaded by libinput and pointer interaction worked in
  the visible Firefox and console applications.

## Remaining M0 gate

The Proxmox VM has basic VGA/scfb but no guest DRM render device. The nested
X11/pixman lane is supplemental and does not close the direct DRM/KMS gate.
That gate remains for a future Intel/AMD passthrough or another FreeBSD-tested
graphics path. No project files were copied into `/usr/bin` or `/usr/lib`.

## Deferred display decision

On 2026-08-06, multi-display Layer Shell validation was intentionally skipped
to keep the development lane moving. The current evidence is single-display
only; multi-display behavior remains an explicit M1 release gate and is not
being claimed as passed.

## M2 session entry-point evidence

- The unprivileged supervisor tests passed bounded shell restart, exact
  compositor ownership, duplicate-session rejection, D-Bus handoff, and
  clean lock release.
- Native `make test` passed on NSTAR-DEV01, including a staged CMake install
  check for the executable `northstar-session`, `northstar-shell`, and
  `share/wayland-sessions/northstar.desktop` files.
- The live `make shell-smoke` check still passed with the existing shell at
  PID 9782 as `northstar` on `wayland-1`. The active nested console session

- The supervised nested `.xinitrc` wrapper was validated with fake compositor,
  shell, and supervisor executables. It passed the patched Wayfire path,
  `northstar-session` path, shell path, and X11/pixman renderer variables
  without starting a graphical session.
- The live supervised `startx` session stayed up with `northstar-session`,
  Wayfire, QTerminal, and `northstar-shell` active on `wayland-1`; the user
  confirmed mouse and keyboard interaction with Firefox and the console.
- The supervisor's readiness and actual-socket discovery fixes passed the
  native suite and were installed before the live run.
- The SDDM boundary is documented and the standard Wayland descriptor remains
  installable, but SDDM was not enabled and no autologin configuration was
  changed.
